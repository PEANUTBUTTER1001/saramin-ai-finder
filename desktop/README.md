# 사람인 공고 관리 PC 앱

## 실행

`desktop/dist/SaraminFinder/실행.bat`를 더블클릭합니다. 배포 폴더에는 Python과 필요한 라이브러리가 포함되므로 대상 PC에 Python을 설치할 필요가 없습니다. `.bat` 시작 순간에는 콘솔 창이 잠깐 보일 수 있지만 GUI 사용 중에는 남지 않습니다. 설치 프로그램은 사용하지 않습니다.

첫 실행 시 `%LOCALAPPDATA%\SaraminAIFinder\jobs.sqlite3`가 생성됩니다. 수집한 공고·자격요건·우대사항·감시 조건·알림은 여기에 보관됩니다. 오류 로그는 같은 위치의 `desktop.log`입니다.

## 개발·배포물 생성

Windows 64비트 및 Python 3.12 개발 환경에서 다음을 실행합니다.

```powershell
python -m pip install -e "desktop[test]"
python -m pytest -q --basetemp desktop/.pytest-tmp desktop/tests
python desktop/packaging/build_portable.py
```

마지막 명령은 공식 Python 3.12.10 내장용 실행 환경과 고정 버전 의존성을 받아 `desktop/dist/SaraminFinder/`를 만듭니다. 대상 PC에서는 다운로드나 `pip`가 필요하지 않습니다.

프로토타입 화면을 다시 동기화할 때만 `python desktop/tools/build_ui.py`를 실행합니다. 이 스크립트는 현재 프로토타입의 HTML/CSS를 가져오고 샘플 JavaScript 대신 실제 `app.js`를 연결합니다.

## 동작 기준

- 수동 수집은 검색어·1/3/10페이지와 지역(복수 선택 가능)·경력 종류/최대 연차·학력을 **수집 작업**에서 설정합니다. 감시의 공통 검색 조건을 기본값으로 불러오지만 수동 수집에서 바꾼 값은 감시 설정을 바꾸지 않습니다. **감시 조건 다시 불러오기**로 현재 기본값을 다시 적용할 수 있습니다. 각 수집 작업에 적용 조건을 기록합니다. 기본값은 서울 전체, 신입~경력 3년, 학력무관/4년제 대졸 이상입니다.
- **공고 감시 → 공통 검색 조건**에서 기본 지역·경력·학력을 변경하면 모든 감시에 적용되며 감시 기준 목록을 새 조건으로 다시 만듭니다. 다음에 앱을 열 때 수동 수집에도 새 기본값으로 표시됩니다.
- 목록에 표시된 `등록일`과 `수정일`은 별도로 저장합니다. `수정일`만 보이는 공고는 등록일을 `미확인`으로 표시합니다. 채용마감일도 원문과 정렬 가능한 날짜로 저장하며, 연도가 없는 `월/일` 표기는 수집일 기준 가장 가까운 미래 날짜로 해석합니다. 상시채용 등 날짜가 없는 공고는 D-Day를 표시하지 않습니다. 기존 저장 공고의 새 날짜 필드는 다음 수집에서 갱신됩니다.
- **공고 데이터**에서 등록일 최근/오래된순, 채용마감 D-Day 짧은/긴순으로 정렬하고 사람인 원본 링크를 엽니다. 마감된 공고와 날짜 미확인 공고는 D-Day 정렬 뒤에 배치합니다. 분석 CSV에도 등록일·마감일·마감 원문을 포함합니다.
- **공고 데이터**와 **요건 분석**에서 직무 분야·경력·기술 키워드를 각각 여러 개 체크할 수 있습니다. 같은 필터의 선택값은 하나라도 일치하면 포함하고, 서로 다른 필터는 모두 일치해야 합니다. 필터마다 **선택 초기화**, 탭마다 **전체 초기화**를 제공합니다. 분석 CSV도 화면과 동일한 조건을 적용합니다. 공고의 분야 원문은 유지하면서 쉼표로 나눈 중복 없는 키워드를 별도로 저장하며 기존 공고에도 업그레이드 시 적용합니다.
- **공고 감시 → 새 공고 알림**과 **요건 분석**의 각 공고에서 앱 내 상세 보기와 **브라우저에서 열기 →**를 함께 제공합니다. 브라우저 버튼은 저장된 사람인 원본 URL을 사용합니다. 실행 중 UI 파일을 갱신한 경우 앱을 다시 열어야 화면에 반영됩니다.
- **설정**에서 전체 화면 글자 크기를 80~140%까지 10% 단위로 조절하고 100%로 복원할 수 있습니다. 선택값은 같은 PC의 공고 DB에 저장되어 다음 실행에도 적용됩니다. `desktop/font/`의 Pretendard 굵기별 파일은 portable 배포 폴더에 포함됩니다.
- 새 데이터베이스에는 `AI` 검색어의 60분 간격 감시 조건이 기본 등록됩니다. 이전 버전 DB를 처음 열 때도 AI 조건이 없으면 한 번 추가하며 기존 감시 목록은 유지합니다. 새 버전에서 사용자가 삭제한 기본 조건은 다시 만들지 않습니다. 검색어·간격은 감시 목록의 **수정**에서 바꿀 수 있습니다.
- 4년제 대졸 이상 조건은 현재 사람인 검색 응답에서 확인한 `edu_cd=8`을 사용합니다. 이전 배포판의 학력 코드 `4`는 데이터베이스를 열 때 `8`로 바꾸고 감시 기준 목록을 다시 만듭니다. 기존 공고와 알림은 유지됩니다.
- **감시 시작**을 누른 조건은 즉시 한 번 확인하고 이후 해당 조건의 설정 간격마다 자동 확인합니다. 여러 조건은 한 번에 하나씩 순차 실행하며, 작업 시간만큼 늦어질 수 있습니다. **일시정지**하면 이후 예약 확인이 멈춥니다. 앱을 완전히 종료하거나 다시 열면 모든 감시는 중지 상태로 시작하며 다시 **감시 시작**을 눌러야 합니다. 창을 최소화한 채 앱이 실행 중이면 감시가 계속됩니다. 감시 화면의 **지금 확인**은 중지 상태에서도 1회 실행할 수 있습니다. **수집 작업** 탭은 **수집 시작**을 눌렀을 때만 실행합니다.
- 감시 확인은 등록일순 결과를 사용합니다. 첫 성공 확인은 기준 목록을 만들고 이후 처음 발견한 공고 ID를 앱의 공고별 알림 목록에 보관합니다. 성공·실패 후 다음 자동 확인은 작업 완료 시각부터 설정 간격을 적용합니다.
- Windows 알림과 앱 안의 팝업은 수집·감시 작업이 완료될 때마다 통계 한 건으로 표시합니다. 새 공고가 0건이거나 수집이 실패해도 작업 결과 한 건을 표시합니다. Windows 시스템 설정에 따라 실제 배너 표시 여부는 달라질 수 있습니다.
- HTTP 요청 사이에 0.5~1.0초 무작위 지연을 둡니다. 재시도에도 적용하며, 첫 요청에는 지연이 없습니다. 실패 시 별도 1초 대기 후 한 번 재시도하고 요청 제한 시간은 12초입니다. 현재 지연 범위는 `src/saramin_finder/infrastructure/saramin.py`의 `SaraminClient` 기본값에 있습니다.
- 수집 이력의 **DB 첫 저장**은 이 PC DB에 처음 나타난 ID 수, **기존 ID 재확인**은 이미 저장된 ID를 다시 확인한 수입니다. 둘 다 실제 사이트의 신규·수정 건수로 해석하지 않습니다. **상세 실패**는 상세 요청 실패 수이며 다른 수치와 겹칠 수 있습니다.
- **새로 발견**은 같은 검색어·조건·페이지 수의 직전 성공 작업에 없고 이번에는 있는 ID 수입니다. 그중 사람인의 명시적 공고등록일이 직전 작업의 한국 날짜보다 늦으면 **등록일로 신규 확인**에 포함합니다. 등록일이 같거나 미확인인 공고는 신규 등록으로 단정하지 않습니다.
- **실제 수정**은 두 작업에 모두 나온 공고에서 목록 값 또는 정상적으로 읽은 상세 텍스트가 달라진 수입니다. **이번 검색 미검출**은 직전 성공 작업에는 있고 이번의 완전한 목록 결과에는 없는 수입니다. 이는 페이지 수 제한·정렬 변화로도 생길 수 있습니다. 그중 원본 페이지에서 명시적 마감 문구를 확인한 공고만 **원본 종료 확인**에 포함합니다. 접근 실패·404·마감 예정일 경과는 종료로 세지 않습니다. 각 항목의 공고는 작업 진행 이력의 **공고별 변화 보기**에서 열 수 있습니다.
- 기존 DB는 공고·알림을 보존하며 v6로 확장됩니다. 과거 작업은 당시 공고 내용이 저장되지 않았으므로 새 지표를 소급 계산하지 않습니다. 업그레이드 후 첫 성공 작업이 비교 기준입니다. 목록 확인이 중간에 실패하면 미검출·종료를 표시하지 않습니다.
- 자격요건과 우대사항은 별도 섹션과 기술 키워드로 저장됩니다. 제목이 없거나 읽을 수 없는 공고는 추출 상태를 표시합니다.
- 사람인 페이지 구조나 접근 정책이 바뀌면 수집이 실패할 수 있습니다. 실패 시 기존 저장 데이터는 유지됩니다.
