# 사람인 공고 관리 PC 앱

## 설치·실행

1. 저장소를 내려받습니다: `git clone` 후 저장소 폴더를 엽니다.
2. 루트의 `설치.bat`를 더블클릭합니다. 배포 폴더를 만들고, 바탕화면에 **사람인 공고 관리** 바로가기를 만든 뒤 앱을 실행합니다. 처음에는 Python 실행 환경과 라이브러리를 내려받아 몇 분 걸립니다.
3. 이후에는 바탕화면 바로가기를 더블클릭합니다.

준비 단계에는 Windows 10 1803 이상(64비트)과 인터넷이 필요합니다. pip가 포함된 Python 3.9 이상(`py -3` 또는 `python`)이 있으면 그것으로 준비하고, 없으면 공식 Python 3.12.10 내장용 실행 환경과 pip 26.2.2 zipapp을 `desktop/.cache/python-boot/`에 받아 사용합니다. 시스템 설치·PATH·레지스트리 변경이나 관리자 권한은 없으며 Windows 기본 `curl`·`tar`로 내려받습니다. 앱은 배포 폴더에 포함된 Python 3.12로 실행되므로 준비가 끝난 폴더는 Python 없는 PC로 복사해도 `실행.bat`로 실행됩니다. 설치 프로그램은 사용하지 않습니다.

업데이트: 앱을 종료하고 `git pull` 후 `설치.bat`를 다시 실행합니다. 앱이 실행 중이면 배포 폴더를 지우지 않고 종료를 안내합니다. 공고 DB는 배포 폴더 밖에 있어 유지됩니다.

첫 실행 시 `%LOCALAPPDATA%\SaraminAIFinder\jobs.sqlite3`가 생성됩니다. 수집한 공고·자격요건·우대사항·즐겨찾기·감시 조건·알림·감시 수집시각·화면 설정은 여기에 보관됩니다. 오류 로그는 같은 위치의 `desktop.log`입니다.

## 개발·배포물 생성

개발·테스트는 Windows 64비트 및 Python 3.12 환경에서 저장소 루트를 기준으로 실행합니다. 아래 `python`은 Python 3.12 환경을 가리켜야 합니다. 설치·배포물 준비에 사용할 수 있는 Python 3.9 이상과 개발용 실행 환경은 구분합니다.

```powershell
python -m pip install -e "desktop[test]"
python -m pytest -q --basetemp desktop/.pytest-tmp desktop/tests
```

화면 동작을 변경한 경우 Node.js가 있는 환경에서 `node --check desktop/src/saramin_finder/ui/app.js`로 JavaScript 구문을 확인합니다. 배포물 생성 후에는 아래 명령으로 실제 Qt/HTML 연결을 검사합니다. 검증 데이터는 `desktop/.smoke/`의 격리 DB에 저장하며 사용자 공고 DB를 사용하지 않습니다.

```powershell
$env:SARFINDER_SMOKE_OFFSCREEN = "1"
& .\desktop\dist\SaraminFinder\runtime\python.exe .\desktop\tools\gui_smoke.py workbench
& .\desktop\dist\SaraminFinder\runtime\python.exe .\desktop\tools\gui_smoke.py workbench_restore
& .\desktop\dist\SaraminFinder\runtime\python.exe .\desktop\tools\gui_smoke.py profile
```

`workbench`는 두 모드·9개 화면·900/1280px·80/100/140%와 즐겨찾기·CSV·새 공고 최대 3열 배치를, `workbench_restore`는 재실행 복원을, `profile`은 공통 검색 조건 저장을 검사합니다. 실행되는 것은 격리된 UI 검사이며 실제 사람인 수집·Windows 알림 배너 표시는 별도 확인 대상입니다.

배포물만 만들 때는 `python desktop/packaging/build_portable.py`를 실행합니다(`설치.bat`의 1단계와 같음). 공식 Python 3.12.10 내장용 실행 환경과 고정 버전 의존성의 Python 3.12 win_amd64 휠을 받아 `desktop/dist/SaraminFinder/`를 만들므로, 빌드하는 Python은 3.9 이상이면 버전이 달라도 됩니다. 대상 PC에서는 다운로드나 `pip`가 필요하지 않습니다.

앱의 실행 화면은 `src/saramin_finder/ui/index.html`과 `app.js`입니다. `workbench.css`는 화면 생성용 기본 스타일이며, `python desktop/tools/build_ui.py`가 글자 크기 보정·여백 배율을 적용해 `index.html`을 생성하도록 구현되어 있습니다. 다만 현재 `main`에는 이 스크립트의 입력인 `outputs/saramin-desktop-prototype.html`이 삭제된 상태이므로 화면 재생성 명령은 입력 원본 확보 전까지 실행할 수 없습니다. 일반 설치·배포물 생성은 저장소에 있는 `index.html`을 사용하며 이 재생성 명령을 호출하지 않습니다.

## 동작 기준

- 수동 수집은 검색어·1/3/10페이지와 지역(복수 선택 가능)·경력 종류/최대 연차·학력을 **수집 작업**에서 설정합니다. 감시의 공통 검색 조건을 기본값으로 불러오지만 수동 수집에서 바꾼 값은 감시 설정을 바꾸지 않습니다. **감시 조건 다시 불러오기**로 현재 기본값을 다시 적용할 수 있습니다. 각 수집 작업에 적용 조건을 기록합니다. 기본값은 서울 전체, 신입~경력 3년, 학력무관/4년제 대졸 이상입니다.
- **공고 감시 → 공통 검색 조건**에서 기본 지역·경력·학력을 변경하면 모든 감시에 적용되며 감시 기준 목록을 새 조건으로 다시 만듭니다. 다음에 앱을 열 때 수동 수집에도 새 기본값으로 표시됩니다.
- 목록에 표시된 `등록일`과 `수정일`은 별도로 저장합니다. `수정일`만 보이는 공고는 등록일을 `미확인`으로 표시합니다. 채용마감일도 원문과 정렬 가능한 날짜로 저장하며, 연도가 없는 `월/일` 표기는 수집일 기준 가장 가까운 미래 날짜로 해석합니다. 상시채용 등 날짜가 없는 공고는 D-Day를 표시하지 않습니다. 기존 저장 공고의 새 날짜 필드는 다음 수집에서 갱신됩니다.
- **공고 데이터**에서 등록일 최근/오래된순, 채용마감 D-Day 짧은/긴순으로 정렬하고 사람인 원본 링크를 엽니다. 마감된 공고와 날짜 미확인 공고는 D-Day 정렬 뒤에 배치합니다. 분석 CSV에도 등록일·마감일·마감 원문을 포함합니다.
- **공고 데이터 → CSV 저장**은 현재 검색·필터·값별 분류·정렬을 적용한 전체 결과를 저장합니다. 현재 페이지만 저장하지 않으며, 상세 추출 실패 공고도 포함합니다. 번호·즐겨찾기·공고 ID·회사·제목·분야·경력·학력·날짜·수집 및 감시 시각·상세 상태·기술 스택·자격요건·우대사항·검색어·원본 URL을 UTF-8 BOM CSV로 내보냅니다.
- 본문 상단 헤더 맨 왼쪽 아이콘으로 사이드바를 축소하고 다시 누르면 확대합니다. 축소 상태는 다음 실행에도 유지되며 메뉴 아이콘에 마우스를 올리면 메뉴 이름을 확인할 수 있습니다.
- 전체 화면은 **데이터 워크벤치** 디자인과 메인 색상 `#2D67FF`를 사용합니다. 표·폼·구분선 중심으로 구성하고 **공고 데이터 → 값별 분류** 버튼으로 분류 도구를 열고 닫습니다. 사이드바의 `Workspace` 표제는 제거하고, 본문 상단의 현재 화면 경로 앞에 축소·확대 아이콘을 배치합니다. 대시보드 최근 수집 공고의 수집 날짜는 한 줄로 표시합니다.
- 상단의 해·달 아이콘 스위치 또는 **설정 → 화면 모드**에서 라이트·다크를 전환합니다. 상단 우측에는 모드 이름과 스위치만 표시하며 로컬 데이터 안내 문구는 제거합니다. 선택한 모드는 기존 공고 DB의 설정에 저장되어 다음 실행에도 복원됩니다. 이전 DB에 모드 설정이 없으면 라이트로 시작하며, 공고·감시·알림 데이터와 기존 설정은 유지합니다.
- **공고 감시**에는 공통 검색 조건과 감시 조건을 표시하며, 감시 방식·검색 조건 요약 안내는 제거합니다. 기존 새 공고 알림 목록은 사이드바에서 **공고 감시 바로 아래 새 공고**로 이동합니다. 알림 건수 배지도 새 공고 메뉴에 표시하며 기존 알림·즐겨찾기·수집 시각·상세·원본 링크는 유지합니다.
- **새 공고**의 알림은 한 줄 최대 3개로 표시하며 화면의 실제 목록 폭과 글자 크기에 따라 2열·1열로 줄입니다. 각 공고의 액션은 내용 아래에 배치하고 긴 제목·회사·수집 시각은 생략하지 않습니다.
- **공고 데이터**와 **새 공고 알림**의 맨 왼쪽 별표로 즐겨찾기를 등록·해제합니다. 공고 ID 기준으로 상태를 공유하며 재수집·재실행 후에도 유지됩니다. 사이드바 **즐겨찾기**에서 선택한 공고만 조회·정렬하고 상세와 원본 링크를 열 수 있습니다.
- **공고 데이터**의 채용마감일 오른쪽 **수집시각**에는 최근 수집 시각과 별도의 최근 감시 수집 시각을 표시합니다. 날짜와 경력 문구는 중간에서 줄바꿈하지 않습니다. 감시로 수집할 때 최초·최근 감시 수집 시각을 별도 저장하며 상세에서 확인할 수 있습니다. 새 공고 알림에는 해당 알림 당시 감시 수집 시각과 알림 생성 시각을 구분해 표시합니다. 과거에 기록하지 않은 감시 수집 시각은 추정하지 않으며, 업그레이드 후 다음 감시 수집부터 기록합니다.
- **공고 데이터**와 **요건 분석**에서 직무 분야·경력·기술 키워드를 각각 여러 개 체크할 수 있습니다. 같은 필터의 선택값은 하나라도 일치하면 포함하고, 서로 다른 필터는 모두 일치해야 합니다. 필터마다 **선택 초기화**, 탭마다 **전체 초기화**를 제공합니다. 분석 CSV도 화면과 동일한 조건을 적용합니다. 공고의 분야 원문은 유지하면서 쉼표로 나눈 중복 없는 키워드를 별도로 저장하며 기존 공고에도 업그레이드 시 적용합니다.
- **새 공고**와 **요건 분석**의 각 공고에서 앱 내 상세 보기와 **브라우저에서 열기 →**를 함께 제공합니다. 브라우저 버튼은 저장된 사람인 원본 URL을 사용합니다. 실행 중 UI 파일을 갱신한 경우 앱을 다시 열어야 화면에 반영됩니다.
- **설정**에서 전체 화면 글자 크기를 80~140%까지 10% 단위로 조절하고 100%로 복원할 수 있습니다. 선택값은 같은 PC의 공고 DB에 저장되어 다음 실행에도 적용됩니다. `desktop/font/`의 Pretendard 굵기별 파일은 portable 배포 폴더에 포함됩니다.
- 기본 글자 크기는 최초 워크벤치 기준에 3 CSS px를 더하고 기존 80~140% 설정을 적용합니다. 화면·표·폼·메뉴의 패딩·마진·항목 간격은 최초 기준의 88%이며, 사이드바 상하 패딩·메뉴 세로 간격은 여기에서 20% 추가 확대합니다. 아이콘·스위치 크기는 유지합니다. 큰 글자와 좁은 창에서는 헤더를 두 줄로 배치하되 우측 모드 이름과 스위치는 나란히 유지합니다.
- **공고 데이터 → 조회 결과**의 표는 헤더·목록 행·마우스 오버의 채움 배경 없이 구분선으로만 구획합니다. 버튼과 즐겨찾기 표시는 유지합니다.
- 새 데이터베이스에는 `AI` 검색어의 60분 간격 감시 조건이 기본 등록됩니다. 이전 버전 DB를 처음 열 때도 AI 조건이 없으면 한 번 추가하며 기존 감시 목록은 유지합니다. 새 버전에서 사용자가 삭제한 기본 조건은 다시 만들지 않습니다. 검색어·간격은 감시 목록의 **수정**에서 바꿀 수 있습니다.
- 4년제 대졸 이상 조건은 현재 사람인 검색 응답에서 확인한 `edu_cd=8`을 사용합니다. 이전 배포판의 학력 코드 `4`는 데이터베이스를 열 때 `8`로 바꾸고 감시 기준 목록을 다시 만듭니다. 기존 공고와 알림은 유지됩니다.
- **감시 시작**을 누른 조건은 즉시 한 번 확인하고 이후 해당 조건의 설정 간격마다 자동 확인합니다. 여러 조건은 한 번에 하나씩 순차 실행하며, 작업 시간만큼 늦어질 수 있습니다. **일시정지**하면 이후 예약 확인이 멈춥니다. 앱을 완전히 종료하거나 다시 열면 모든 감시는 중지 상태로 시작하며 다시 **감시 시작**을 눌러야 합니다. 창을 최소화한 채 앱이 실행 중이면 감시가 계속됩니다. 감시 화면의 **지금 확인**은 중지 상태에서도 1회 실행할 수 있습니다. **수집 작업** 탭은 **수집 시작**을 눌렀을 때만 실행합니다.
- 감시 확인은 등록일순 결과를 사용합니다. 첫 성공 확인은 기준 목록을 만들고 이후 처음 발견한 공고 ID를 앱의 공고별 알림 목록에 보관합니다. 성공·실패 후 다음 자동 확인은 작업 완료 시각부터 설정 간격을 적용합니다.
- Windows 알림과 앱 안의 팝업은 수집·감시 작업이 완료될 때마다 통계 한 건으로 표시합니다. 새 공고가 0건이거나 수집이 실패해도 작업 결과 한 건을 표시합니다. Windows 시스템 설정에 따라 실제 배너 표시 여부는 달라질 수 있습니다.
- HTTP 요청 사이에 0.5~1.0초 무작위 지연을 둡니다. 재시도에도 적용하며, 첫 요청에는 지연이 없습니다. 실패 시 별도 1초 대기 후 한 번 재시도하고 요청 제한 시간은 12초입니다. 현재 지연 범위는 `src/saramin_finder/infrastructure/saramin.py`의 `SaraminClient` 기본값에 있습니다.
- 수집 이력의 **DB 첫 저장**은 이 PC DB에 처음 나타난 ID 수, **기존 ID 재확인**은 이미 저장된 ID를 다시 확인한 수입니다. 둘 다 실제 사이트의 신규·수정 건수로 해석하지 않습니다. **상세 실패**는 상세 요청 실패 수이며 다른 수치와 겹칠 수 있습니다.
- **새로 발견**은 같은 검색어·조건·페이지 수의 직전 성공 작업에 없고 이번에는 있는 ID 수입니다. 그중 사람인의 명시적 공고등록일이 직전 작업의 한국 날짜보다 늦으면 **등록일로 신규 확인**에 포함합니다. 등록일이 같거나 미확인인 공고는 신규 등록으로 단정하지 않습니다.
- **실제 수정**은 두 작업에 모두 나온 공고에서 목록 값 또는 정상적으로 읽은 상세 텍스트가 달라진 수입니다. **이번 검색 미검출**은 직전 성공 작업에는 있고 이번의 완전한 목록 결과에는 없는 수입니다. 이는 페이지 수 제한·정렬 변화로도 생길 수 있습니다. 그중 원본 페이지에서 명시적 마감 문구를 확인한 공고만 **원본 종료 확인**에 포함합니다. 접근 실패·404·마감 예정일 경과는 종료로 세지 않습니다. 각 항목의 공고는 작업 진행 이력의 **공고별 변화 보기**에서 열 수 있습니다.
- 기존 DB는 공고·알림을 보존하며 v7로 확장됩니다. 과거 작업은 당시 공고 내용이 저장되지 않았으므로 새 지표를 소급 계산하지 않습니다. 업그레이드 후 첫 성공 작업이 비교 기준입니다. 목록 확인이 중간에 실패하면 미검출·종료를 표시하지 않습니다.
- 자격요건과 우대사항은 별도 섹션과 기술 키워드로 저장됩니다. 제목이 없거나 읽을 수 없는 공고는 추출 상태를 표시합니다.
- 사람인 페이지 구조나 접근 정책이 바뀌면 수집이 실패할 수 있습니다. 실패 시 기존 저장 데이터는 유지됩니다.
